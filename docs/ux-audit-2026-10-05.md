La nota es una valoración heurística del código, no una medición de satisfacción ni una certificación de accesibilidad. La normalización evita penalizar funcionalidades que este flujo no necesita.

Se reconoce que es una demo: no se penaliza la ausencia de pasarela de pago, cuentas o descuento de stock como si fueran requisitos implementados. Sí se evalúa que los textos y estados describan correctamente esa demo. No se proponen urgencia, reseñas, métricas de actividad ni datos comerciales inventados.

## Critical Issues (2)

### Fitts’s Law — Score: 0/2

**Problem:** el botón `+` sólo tiene `px-1`, fuente de 18 px y `leading-none`; los botones de talle sólo tienen texto de 11 px y, en la ficha, `pb-1`. El espacio entre botones no aumenta su superficie táctil. Esto afecta acciones repetidas del flujo, aunque el CTA principal sí tiene padding suficiente. Evidencia: [quick-add.tsx:38](/D:/ClothesShop/components/quick-add.tsx:38), [quick-add.tsx:50](/D:/ClothesShop/components/quick-add.tsx:50), [add-to-cart.tsx:39](/D:/ClothesShop/components/add-to-cart.tsx:39). También revisar “Quitar” en [carrito/page.tsx:109](/D:/ClothesShop/app/carrito/page.tsx:109).

**Fix:** dar a los controles una superficie de al menos 44 × 44 px como objetivo de diseño táctil. Medir las cajas finales en móvil; al agrandar los talles, permitir que el panel se ajuste al ancho disponible.

```tsx
// Before (components/quick-add.tsx, line 38)
className="px-1 text-lg leading-none text-muted transition-colors duration-300 ease-out hover:text-ink"

// After — mismo botón y comportamiento
className="inline-flex min-h-11 min-w-11 items-center justify-center text-lg text-muted transition-colors duration-200 hover:text-ink"

// Talles: incorporar estas utilidades a las clases existentes.
// Panel: permitir flex-wrap y comprobar que no exceda el viewport.
// min-h-11 min-w-11 inline-flex items-center justify-center
```

### Jakob’s Law — Score: 0/2

**Problem:** al borrar el `1` para escribir `2`, `Number('')` devuelve `0` y `setQty` elimina el producto. Si era el último, se desmonta también el formulario de envío y se pierde lo escrito. `min` y `max` no impiden la escritura manual de otros valores; ese input está fuera del formulario de checkout. Evidencia: [carrito/page.tsx:103](/D:/ClothesShop/app/carrito/page.tsx:103) y [cart.tsx:138](/D:/ClothesShop/components/cart.tsx:138). Reproducción local de la transformación: entrada vacía → cantidad 0 → cero líneas.

**Fix:** mantener la eliminación en “Quitar”. Para el rango actual 1–20, un selector nativo evita estados de edición ambiguos. Si se conserva el input numérico, necesita un borrador de texto y validación al confirmar la edición.

```tsx
// Before (app/carrito/page.tsx, line 103)
onChange={(e) => setQty(item.slug, item.size, Number(e.target.value))}

// After — sustituir el input, conservando el label existente
<select
  id={`qty-${item.slug}-${item.size}`}
  value={item.qty}
  disabled={pending}
  onChange={(e) => setQty(item.slug, item.size, Number(e.target.value))}
  className="min-h-11 min-w-16 border border-line bg-paper px-2"
>
  {Array.from({ length: 20 }, (_, i) => i + 1).map((qty) => (
    <option key={qty} value={qty}>{qty}</option>
  ))}
</select>

// En CartProvider: una cantidad inválida no elimina la línea.
const setQty = (slug: string, size: string, qty: number) => {
  if (!Number.isInteger(qty) || qty < 1 || qty > 20) return
  update((prev) => prev.map((i) =>
    sameLine(i, slug, size) ? { ...i, qty } : i
  ))
}
```

El mismo límite debe regir en `add`, actualmente acumulativo sin tope, y en la lectura de cantidades persistidas. Al alcanzar el máximo, informar el límite: no afirmar “Agregado” si no se agregó nada.

## Warnings (9)

### Cognitive Load — Score: 1/2

**Problem:** “Elegí tu talle” aparece con el primer talle ya seleccionado por `useState(product.sizes[0] ?? '')`. Es posible agregarlo sin advertir la elección implícita. El añadido rápido, en cambio, exige elegir. Evidencia: [add-to-cart.tsx:9](/D:/ClothesShop/components/add-to-cart.tsx:9).

**Fix:** para varios talles, empezar sin selección y mantener una instrucción visible. Una única variante sí puede preseleccionarse; conservar el comportamiento de productos sin variantes hasta definir su modelo.

```tsx
const [size, setSize] = useState(
  product.sizes.length === 1 ? product.sizes[0] : ''
)
const needsSize = product.sizes.length > 0 && !size
// En onAdd, antes de add(): if (soldOut || needsSize) return
// En el botón: disabled={soldOut || needsSize}
// Texto cuando needsSize: 'Elegí un talle para agregar'
```

No inventar medidas para una guía de talles: incorporarla cuando existan datos reales.

### Doherty Threshold — Score: 1/2

**Problem:** existe `Procesando…` en checkout y feedback inmediato al añadir, pero las páginas esperan datos sin `loading.tsx` ni fallback de Suspense propio. No se afirma que la respuesta supere 400 ms: no se midió. Además, una excepción de transporte en `await checkout(...)` no se transforma en el error local del formulario. Evidencia: [app/page.tsx:31](/D:/ClothesShop/app/page.tsx:31), [producto/page.tsx:19](/D:/ClothesShop/app/producto/[slug]/page.tsx:19) y [carrito/page.tsx:27](/D:/ClothesShop/app/carrito/page.tsx:27).

**Fix:** añadir `app/loading.tsx` y, si hace falta una silueta distinta, `app/producto/[slug]/loading.tsx`, con estructura similar al contenido y texto `role="status"`. Para cambios de filtro dentro de la misma ruta, verificar el pending real y usar un límite de Suspense con clave de categoría o feedback del enlace cuando corresponda. No asumir que el archivo de carga cubre cada transición.

```tsx
// Nuevo loading.tsx, base mínima; completar con bloques del layout real.
export default function Loading() {
  return <p role="status" className="px-6 py-16">Cargando prendas…</p>
}
```

En `startTransition`, envolver la llamada y el procesamiento del resultado en `try/catch`, conservando carrito y campos. Ante error de transporte, mostrar que no se pudo confirmar el estado; antes de ofrecer reintento automático, implementar una clave idempotente para no duplicar un pedido que pudo haberse guardado.

### Flow — Score: 1/2

**Problem:** los enlaces de categoría apuntan a `/?categoria=…` sin `#catalogo`, aunque los resultados están después de Hero, Highlights y Manifesto. Desde producto o desde arriba de la portada no conducen directamente al resultado. No se atribuye a todos los cambios de filtro un salto al inicio: Next puede conservar el scroll. Evidencia: [app/page.tsx:278](/D:/ClothesShop/app/page.tsx:278), [site-header.tsx:79](/D:/ClothesShop/components/site-header.tsx:79) y [mobile-nav.tsx:31](/D:/ClothesShop/components/mobile-nav.tsx:31).

**Fix:** homogeneizar esos destinos también en pie y ficha, usando el ancla existente; marcar la categoría activa semánticamente.

```tsx
<Link
  href={`/?categoria=${c.slug}#catalogo`}
  aria-current={active === c.slug ? 'page' : undefined}
>
  {c.label}
</Link>
```

**Segundo problema del mismo flujo:** durante `pending` sólo se deshabilita enviar. Cantidad y “Quitar” siguen activos; al resolver el pedido se llama a `clear()` sobre el carrito actual, aunque la petición ya contiene una instantánea anterior. Evidencia: [carrito/page.tsx:34](/D:/ClothesShop/app/carrito/page.tsx:34), [carrito/page.tsx:38](/D:/ClothesShop/app/carrito/page.tsx:38) y [carrito/page.tsx:108](/D:/ClothesShop/app/carrito/page.tsx:108).

**Fix:** deshabilitar edición y eliminación durante el envío; añadir `aria-busy={pending}` al formulario. Para cubrir otras pestañas o navegación, reemplazar `clear()` por una operación que consuma únicamente las cantidades efectivamente confirmadas de la instantánea enviada y preserve adiciones posteriores. Si el carrito cambió de forma incompatible, conservarlo y ofrecer conciliación explícita. El bloqueo visual local por sí solo no resuelve esa concurrencia.

### Serial Position Effect — Score: 1/2

**Problem:** la ficha empieza con una imagen de `72vh` en móvil y `86vh` en escritorio; nombre, precio, talle y CTA vienen después de ella y de `py-14`. La estructura posterga la decisión de compra. Es una conclusión de las dimensiones declaradas, pendiente de validación de viewport. Evidencia: [producto/page.tsx:34](/D:/ClothesShop/app/producto/[slug]/page.tsx:34).

**Fix:** convertir el artículo a dos columnas en escritorio y limitar la imagen en móvil. Punto de partida para comprobar con imágenes reales:

```tsx
// article: className="mx-auto max-w-7xl md:grid md:grid-cols-2 md:gap-10"
// ProductImage: className="h-[48svh] w-full md:h-[70vh]"
// Panel de información: className="w-full px-6 py-8 md:py-12"
```

No agregar un CTA fijo antes de comprobar si esta distribución ya deja visible la compra.

### Peak-End Rule — Score: 0/2

**Problem:** la confirmación dice “Te enviamos los detalles por email”, pero la acción sólo inserta el pedido y devuelve su ID. No hay envío de correo ni trigger correspondiente en los archivos versionados examinados; una integración externa no fue verificada. Es una promesa de resultado que el código auditado no respalda. Evidencia: [carrito/page.tsx:51](/D:/ClothesShop/app/carrito/page.tsx:51) y [actions.ts:103](/D:/ClothesShop/app/carrito/actions.ts:103).

**Fix:** ajustar el mensaje a la demo actual y mostrar una referencia completa seleccionable, más resumen y siguiente acción. No afirmar que un correo se envió sin una señal real del proveedor.

```tsx
<h1>Pedido de prueba registrado</h1>
<p>No se realizó ningún cobro. Guardá esta referencia:</p>
<p className="break-all select-all">{orderId}</p>
<Link href="/#catalogo">Volver al catálogo</Link>
```

También mejorar la recuperación de fallos y vacíos: [app/page.tsx:43](/D:/ClothesShop/app/page.tsx:43) sólo pide reintentar sin control; [app/page.tsx:79](/D:/ClothesShop/app/page.tsx:79) no ofrece quitar el filtro. Añadir una acción de reintento que realmente refresque datos y un enlace `/#catalogo` para restablecer el filtro. Crear límites de error y una página de producto no encontrado con vuelta al catálogo. La documentación instalada de Next usa `retry` como prop de `error.tsx`; verificarla al implementar, sin copiar ejemplos antiguos con `reset`.

### Working Memory — Score: 1/2

**Problem:** al confirmar se borra el carrito y queda sólo un ID truncado en un estado local. El comprador ya no puede consultar artículos, talles, cantidades, envío o total; al recargar vuelve al carrito vacío. Evidencia: [carrito/page.tsx:17](/D:/ClothesShop/app/carrito/page.tsx:17) y [carrito/page.tsx:37](/D:/ClothesShop/app/carrito/page.tsx:37).

**Fix:** hacer que `CheckoutResult` devuelva un recibo calculado por el servidor con ID, líneas e importes; mostrarlo antes de consumir las líneas del carrito. Para la demo, guardar ese recibo en `sessionStorage` con manejo de errores, sin email ni dirección. Ofrecer copiarlo o descargarlo. Una confirmación persistente en servidor requeriría acceso protegido: no abrir la lectura pública de pedidos.

```ts
// Contrato propuesto; requiere implementarlo en acción y página.
type Receipt = {
  orderId: string
  items: { name: string; size: string; qty: number; unit_price_cents: number }[]
  shipping_cents: number
  total_cents: number
}
```

En móvil, mantener además un resumen compacto junto al botón de envío; actualmente sólo el total del botón se conserva cerca de la acción al llegar al final del formulario.

### Postel’s Law — Score: 1/2

**Problem:** `address.trim().min(10)` rechaza una entrada razonable como “Mitre 123” (9 caracteres). El servidor normaliza el CP con `trim`, pero el `pattern` HTML bloquea los espacios exteriores antes de llegar a esa normalización. Evidencia: [actions.ts:11](/D:/ClothesShop/app/carrito/actions.ts:11), [carrito/page.tsx:12](/D:/ClothesShop/app/carrito/page.tsx:12) y [argentina.ts:50](/D:/ClothesShop/lib/argentina.ts:50).

**Fix:** validar contenido requerido sin usar una longitud arbitraria como prueba de dirección válida. Conservar máximos y validaciones de servidor; permitir espacios exteriores en el patrón y normalizarlos en servidor. Agregar atributos de longitud al componente `Field` para alinear límites con el esquema.

```ts
// CheckoutSchema
address: z.string().trim().min(1, 'Escribí calle y número.').max(400),
email: z.string().trim().pipe(z.email('El email no es válido.')).max(200),

// Patrón HTML: admite espacios exteriores, no caracteres internos arbitrarios.
const CP_PATTERN = String.raw`\s*(?:[A-Za-z][0-9]{4}[A-Za-z]{3}|[0-9]{4})\s*`
```

Esta corrección evita falsos rechazos; no constituye validación logística de una dirección. Si se necesita comprobar calle y número por separado, diseñar esos campos y el contrato conjuntamente.

### Tesler’s Law — Score: 1/2

**Problem:** el carrito conserva `price_cents` en almacenamiento local, mientras el servidor vuelve a consultar precios al registrar. Si un precio o promoción cambió desde el añadido, el total mostrado y el guardado pueden diferir; puede cambiar también el envío al cruzar su umbral. El cliente recibe sólo el ID y no ve esa discrepancia. Evidencia: [cart.tsx:155](/D:/ClothesShop/components/cart.tsx:155), [actions.ts:55](/D:/ClothesShop/app/carrito/actions.ts:55) y [actions.ts:81](/D:/ClothesShop/app/carrito/actions.ts:81).

**Fix:** separar cotización y confirmación. La cotización canónica debe actualizar líneas, envío y total del resumen. Al confirmar, el servidor vuelve a verificarla y, si cambió, devuelve los nuevos importes sin insertar hasta que el comprador los acepte. Una huella enviada por el cliente sirve para detectar cambios, nunca como autoridad para fijar precios.

```ts
// Contrato orientativo para extender CheckoutResult.
type QuoteChanged = {
  ok: false
  code: 'QUOTE_CHANGED'
  quote: {
    items: { slug: string; size: string; qty: number; unit_price_cents: number }[]
    shipping_cents: number
    total_cents: number
  }
}
// UI: reemplazar el resumen con quote y solicitar una nueva confirmación.
// Servidor: no hacer INSERT en la rama QUOTE_CHANGED.
```

Comprobar el caso de precio actualizado y el de subtotal que pasa de envío gratuito a pago. No se propone confiar en precios del navegador.

### Mental Model — Score: 1/2

**Problem:** el CTA dice “Pagar” y debajo aclara que no habrá cobro. Además, la ficha muestra `product.category` (“chaquetas”, “sudaderas”), mientras la navegación usa “Camperas” y “Buzos”. Evidencia: [carrito/page.tsx:178](/D:/ClothesShop/app/carrito/page.tsx:178), [producto/page.tsx:64](/D:/ClothesShop/app/producto/[slug]/page.tsx:64) y [shop.ts:95](/D:/ClothesShop/lib/shop.ts:95).

**Fix:** usar `pending ? 'Registrando…' : 'Registrar pedido de prueba'`, manteniendo el total visible al lado del botón y el aviso de demo antes de enviarlo. Resolver la etiqueta de categoría mediante `CATEGORIES.find(c => c.slug === product.category)?.label ?? product.category`, conservando el slug en la URL. Alinear este vocabulario con la confirmación propuesta.

## Suggestions (4)

### Aesthetic-Usability Effect — Score: 1/2

**Improve:** la coherencia estética es una fortaleza. El token `muted` sobre `paper` tiene contraste calculado de **3,45:1**, y `.label`/`.meta` usan 11 px con tamaño raíz de 16 px. Esto reduce la legibilidad de precios, etiquetas y ayuda. Evidencia: [globals.css:6](/D:/ClothesShop/app/globals.css:6), [globals.css:40](/D:/ClothesShop/app/globals.css:40) y [product-card.tsx:39](/D:/ClothesShop/components/product-card.tsx:39). El cálculo es de colores opacos CSS; no mide fotos, transparencias ni render final.

**Code:** cambiar `--color-muted` a `#706c5e` como candidato (contraste calculado **4,97:1** sobre el mismo fondo); subir `.meta` a `0.8125rem` y revisar `.label` a `0.75rem` con tracking menor. Verificar que navegación y tarjetas no desborden después. Aunque la taxonomía de la skill ubica esta ley como pulido, la legibilidad de precios y campos merece prioridad práctica.

### Occam’s Razor — Score: 1/2

**Improve:** “Cartas de Hilo” anuncia correspondencia sin formulario, archivo ni enlace. El comentario confirma que todavía no hay proveedor. Evidencia: [site-footer.tsx:50](/D:/ClothesShop/components/site-footer.tsx:50).

**Code:** retirar por ahora ese bloque y pasar la grilla del pie de `md:grid-cols-4` a `md:grid-cols-3`. Recuperarlo cuando exista una acción útil. No agregar un formulario simulado.

### Pareto Principle — Score: 1/2

**Improve:** al elegir una categoría se siguen renderizando primero Hero, Highlights y Manifesto, aunque la intención es ver prendas de esa categoría. Evidencia: [app/page.tsx:72](/D:/ClothesShop/app/page.tsx:72).

**Code:** mantener la portada editorial en la visita general y reducirla cuando hay filtro:

```tsx
{!active && <><Hero /><Highlights newest={newest} promo={promo} news={latestNews} /><Manifesto /></>}
<CategoryBar active={active} />
```

Este cambio requiere que `SiteHeader` distinga “portada con hero” de “ruta `/` filtrada”: hoy `bleeds` depende sólo de `pathname`. En la vista filtrada debe usar fondo opaco y reservar `--top-h`. Pasar una señal de portada o derivarla de los parámetros siguiendo la documentación instalada. No aplicar sólo el fragmento dejando la cabecera transparente sobre el catálogo. La mejora de conversión es una hipótesis a validar, no un resultado medido.

### Paradox of the Active User — Score: 1/2

**Improve:** el añadido rápido usa `+`, `×` y `✓`; tras elegir talle el selector desaparece y la confirmación sólo dura 1,6 s. Su `aria-label` sigue diciendo “Agregar…” incluso tras el éxito. Evidencia: [quick-add.tsx:22](/D:/ClothesShop/components/quick-add.tsx:22) y [quick-add.tsx:37](/D:/ClothesShop/components/quick-add.tsx:37).

**Code:** incorporar una región persistente `role="status"` fuera del panel que se desmonta, con texto “Agregado al carrito, talle M”, obtenido del talle elegido. Añadir `aria-controls` hacia el panel y una etiqueta visible “Agregar” o “Elegir talle” si el ancho lo permite. Restaurar el foco al disparador cuando una elección desmonta el botón enfocado. No abrir automáticamente el carrito ni interrumpir la exploración.
